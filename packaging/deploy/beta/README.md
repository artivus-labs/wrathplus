# WrathPlus open-beta realm (Hetzner)

The public beta realm runs the **same recipe as the Manager's local realm**:
`packaging/server/compose.yaml`, `Dockerfile`, `runtime.sh` and `credentials.sh`, with the same
pinned core, mod-playerbots and module set, and the Manager's Playerbots settings as AzerothCore
`AC_*` environment overrides. `compose.beta.yaml` overrides only what the public box needs.

| | Local (Manager) | Beta |
| --- | --- | --- |
| Compose project | `wrathplus-managed-local` | `wrathplus-beta` |
| Image | `wrathplus/playerbots:arm64-spike` | `wrathplus/playerbots:amd64-beta` (built on the box, 4 jobs) |
| Auth | `127.0.0.1:13724` | `3724` on all interfaces (IPv4 + IPv6) |
| World | `127.0.0.1:18085` | `8085` on all interfaces |
| SOAP | `127.0.0.1:17878` | `127.0.0.1:17878` (box loopback only) |
| MySQL | not published | not published (Docker network only) |
| Restart | none | `unless-stopped` (mysql, auth, world) |
| World logs | `/state` tmpfs | `world-logs` volume (disk, not RAM) |
| Settings | `server.env` written by Manager | `server.env` here; `/etc/wrathplus-beta/server.env` wins |
| Realm list | `WrathPlus Local`, 127.0.0.1:18085 | `WrathPlus Beta`, wrathplus.artivus.com.au:8085 |

Modules: mod-playerbots, mod-multibot-bridge, mod-quest-minimap-points, mod-party-quest-share
and mod-atproto-identity (the realm side of `services/account`). mod-llm-chatter is
**off** (needs a paid LLM key). The module-config directory is empty: the local realm's saved
`playerbots.conf` equals the shipped `.conf.dist`.

## Files

- `beta.conf` — paths, project, image, realm row, pins. `/etc/wrathplus-beta/beta.conf` overrides.
- `server.env` — Playerbots settings (Manager defaults; population sized for the box, below).
- `compose.beta.yaml` — the override described above.
- `bootstrap-host.sh` — one-time host setup.
- `realm.sh` — everything else (`realm.sh` with no argument lists the commands); installed as
  `/usr/local/sbin/wrathplus-realm`.
- `systemd/` — daily backup service and timer; the account service unit.

## Box layout

```
/srv/wrathplus/repo            this repository (scripts + recipe)
/srv/wrathplus/src             pinned core fork (+ modules/mod-playerbots), mod-multibot-bridge
/srv/wrathplus/build-context   module-only build context (copies, no .git)
/srv/wrathplus/server-data     dbc/ maps/ vmaps/ mmaps/ Cameras/ Buildings/ (read-only mount)
/srv/wrathplus/module-config   private .conf overrides (empty)
/srv/wrathplus/logs            logs of detached runs (realm.sh detach ...)
/srv/wrathplus/build-receipt.txt  image id + revisions of the last build
/etc/wrathplus-beta/           0700: soap-admin.secret, accounts/<NAME> (0600 password files)
/etc/wrathplus/                0750 root:wrathplus-account: account.env, soap-account (0600, service user)
/var/lib/wrathplus-account/    account service state: account.sqlite, oauth-keys.json (0700)
/var/backups/wrathplus/        daily dumps, 7 days
```

MySQL credentials are generated by `credentials.sh` into the `instance-secrets` volume and read
only inside containers. Two SOAP-only gmlevel-3 accounts, both rewritten from their 0600 files on each use: `SOAPADMIN`
(`realm.sh` commands, `/etc/wrathplus-beta/soap-admin.secret`) and `SOAPACCOUNT` (the account
service, `USER:PASSWORD` in `/etc/wrathplus/soap-account`). The account service reserves the
`SOAP` prefix, so no ATProto handle can be issued these names.

## Rebuild from scratch

From a machine with the box's root key (`ssh -i ~/.ssh/wrathplus_hetzner root@<box>`):

```sh
# 1. Host: updates, unattended-upgrades, Docker (+ compose/buildx), 4 GB swap, key-only sshd, fail2ban
ssh root@box 'bash -s' < packaging/deploy/beta/bootstrap-host.sh

# 2. Server data (extracted dbc/maps/vmaps/mmaps..., ~7.2 GB; not client MPQs)
nice -n 15 rsync -a --partial --delete -e ssh /path/to/server/data/ root@box:/srv/wrathplus/server-data/

# 3. Repo, timer + command, then the image build (hours on 4 vCPU; detached, poll it)
ssh root@box
git clone https://github.com/artivus-labs/wrathplus.git /srv/wrathplus/repo
/srv/wrathplus/repo/packaging/deploy/beta/realm.sh install
wrathplus-realm detach build
systemctl is-active wrathplus-build; tail -f /srv/wrathplus/logs/build-*.log

# 4. Start (MySQL, dbimport, realm row, auth + world; waits for health). First start also
#    creates the Playerbots accounts and characters, which takes a while.
wrathplus-realm start
wrathplus-realm status

# 5. Account service: Bun (pinned in beta.conf, 1.4+), services/account as wrathplus-account.service
#    on 127.0.0.1:8787, its SOAP account, Caddy with automatic TLS on 80/443 (needs DNS in place)
wrathplus-realm account-service
```

## Operate

```sh
wrathplus-realm status                 # services, health, docker stats, online characters
wrathplus-realm account NAME           # player account (no GM); password in /etc/wrathplus-beta/accounts/NAME
wrathplus-realm restart                # stop world/auth, bootstrap (DB updates), start
wrathplus-realm soap ".server info"     # one GM command over SOAP (loopback)
wrathplus-realm backup                 # dump now (also daily via wrathplus-backup.timer)
wrathplus-realm detach update          # pull, rebuild, backup, restart on the new image
```

`update` runs `git pull --ff-only` on the box checkout, so that checkout must track the branch
being deployed. Rebuilds reuse BuildKit's ccache; the realm stays up during the build and is
down only for the stop/bootstrap/start at the end. Image rollback does not undo DB migrations:
restore the pre-update dump (`update` takes one) if a module migration has to be reverted.

Changing the bot population or another Playerbots setting: edit `server.env` (or put a copy in
`/etc/wrathplus-beta/server.env`), then `wrathplus-realm restart`; Compose recreates the
servers whose environment changed. Raising the population creates bot accounts on the next start.

After a reboot Docker brings back mysql, auth and world (restart policy `unless-stopped`); auth
and world retry until MySQL accepts connections. A realm stopped with `realm.sh stop` stays
stopped across reboots.

Restore a dump into the running MySQL (stop world and auth first):

```sh
wrathplus-realm stop
gunzip -c /var/backups/wrathplus/wrathplus-beta-<stamp>.sql.gz | \
  docker exec -i wrathplus-beta-mysql-1 sh -c 'MYSQL_PWD=$(cat /run/instance-secrets/mysql-root) exec mysql -uroot'
wrathplus-realm start
```

## Network

The Hetzner Cloud firewall admits only 22, 80, 443, 3724 and 8085. Docker publishes 3724 and 8085
on all interfaces and SOAP on loopback; MySQL has no published port. There is no host firewall
(Docker bypasses ufw's rules for published ports, so it would add nothing here).

## Bot count

The box is a Hetzner **CX43** (8 vCPU, 16 GB; resized from a CX33 on 2026-11-09), and
`server.env` runs **400** random bots (Min = Max). With all 400 online: worldserver 6.7 GB,
MySQL 0.7 GB, 8.3 GB used, 7.3 GB available, no swap; that leaves room for players and agents,
and more bots fit at about 3-5 MB each.

The first measurements, on the CX33 (4 vCPU, 7.57 GiB usable RAM, 4 GB swap), explain why it was
resized. The worldserver's memory is dominated by a
fixed cost, not by bots: mod-playerbots' startup (`TravelMgr::PrepareDestinationCache` and the
travel/taxi caches, about 67-100 s) takes the process from about 1.5 GB to 5 GB before any bot
logs in. `malloc_trim` released nothing, so it is live data.

| Random bots online | worldserver RSS | MySQL | MemAvailable | Swap used | When |
| --- | --- | --- | --- | --- | --- |
| 0 | 5.3-5.5 GB, slowly rising | 0.3 GB | ~1.5 GB | 0.7 GB (left from the 300 run) | 2-5 min after start |
| 100 | 6.1-6.2 GB, flat | 0.6 GB | ~0.4 GB | 0.27 GB | 2-11 min after a reboot |
| 150 | 6.2-6.3 GB, flat | 0.4 GB | ~0.45 GB | ~1.0 GB | 4-11 min after start |
| 300 | 6.8 GB and rising | 0.24 GB | ~0.3 GB | 0.78 GB | 3-8 min after start |

The 70-75 % RAM target is out of reach at any population on this box: with no bots at all the
worldserver alone uses about 70 %, and MySQL, the OS, Caddy and the account service bring it past
80 %. Bots cost about 3-5 MB each on top, so 100 bots leaves room for players while swap holds
cold pages (swap-in stayed at tens of pages a second, no thrashing). For a few hundred bots with
headroom, use a 16 GB box (Hetzner CX43) or cut the playerbots startup caches.
The sampler output from these runs is in `/srv/wrathplus/logs/memlog-20261109.log` on the box.

## Account service

`services/account` (ATProto sign-in; see its README) runs from this checkout as
`wrathplus-account.service` (user `wrathplus-account`, `/etc/wrathplus/account.env`), listening
on `127.0.0.1:8787`. Caddy (`/etc/caddy/Caddyfile` imports `services/account/Caddyfile`) serves
`https://wrathplus.artivus.com.au` with a Let's Encrypt certificate. It talks to the realm only
over SOAP on `127.0.0.1:17878` and polls `.atproto events`. `update` refreshes its dependencies
and restarts it. The daily backup also archives its SQLite (via `VACUUM INTO`) and OAuth signing
keys as `account-service-<stamp>.tar.gz`; losing the keys signs everyone out of record publishing.

```sh
systemctl status wrathplus-account caddy
journalctl -u wrathplus-account -f
curl -s https://wrathplus.artivus.com.au/healthz
```
